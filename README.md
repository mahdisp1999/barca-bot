# ⚽ barca-bot — ربات یادآور بازی‌های بارسلونا

ربات تلگرام (Python) که **برای همه‌ی کاربران مجاز** (ادمین + `ALLOWED_USERS`):

- 📅 بازی‌های بارسلونا را از **SportsAPI Pro** می‌گیرد،
- ⏰ قبل از هر بازی **یادآوری** می‌فرستد (۶۰، ۳۰، ۱۵، ۱۰ و ۵ دقیقه قبل)،
- 📊 بعد از پایان بازی **نتیجه** را می‌فرستد،
- 📡 هر چه به بازی نزدیک می‌شویم، اگر مدتی به کاربر پیامی نرفته باشد، **وضعیت بازی بعدی** را خودکار می‌فرستد،
- 🗓️ با `/status` آخرین نتیجه و بازی بعدی را (با تاریخ شمسی و میلادی) نشان می‌دهد،
- 🗒️ همه‌ی تعامل‌ها (و زمان آخرین پیام هر کاربر) را در SQLite ثبت می‌کند،
- 🔐 فقط به کاربران مجاز جواب می‌دهد.

طراحی، دیاگرام و تصمیم‌ها: [`Architecture.md`](./Architecture.md)

## 🚀 راه‌اندازی سریع

```bash
python -m venv .venv
source .venv/bin/activate            # ویندوز: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                 # و مقدارها را پر کن
python main.py
```

- ✅ بدون `PYTHONPATH` و از هر جایی قابل اجراست.
- ✅ `.env`، `usage.db` و `bot_state.json` همه در **ریشه‌ی پروژه** هستند.
- ✅ با اجرای موفق این پیام را می‌بینی: `ربات آماده است.`

### 📦 پیش‌نیازها

- Python 3.9 یا بالاتر
- توکن ربات از [@BotFather](https://t.me/BotFather) و آیدی عددی خودت (مثلاً از [@userinfobot](https://t.me/userinfobot))
- کلید API از SportsAPI Pro
- اگر تلگرام فیلتر است، آدرس پروکسی Bot API را در `BOT_API_BASE_URL` بگذار

## 👥 کاربران چطور اضافه می‌شوند؟

۱. آیدی عددی‌شان را در `ALLOWED_USERS` بگذار (با کاما جدا کن).
۲. ربات را ری‌استارت کن.
۳. **هر کاربر باید یک‌بار به ربات `/start` بزند.** تلگرام اجازه نمی‌دهد ربات اول به کسی پیام بدهد؛ بدون `/start` ارسال برای او شکست می‌خورد (در لاگ می‌بینی).

از این به بعد هر یادآوری، نتیجه و وضعیت خودکار برای همه‌ی این کاربران می‌رود؛ **هر کاربر هر پیام را فقط یک‌بار می‌گیرد**، حتی بعد از ری‌استارت.

## 🔧 تنظیمات (`.env`)

| متغیر | الزامی؟ | توضیح |
| :--- | :--- | :--- |
| `TELEGRAM_BOT_TOKEN` | ✅ | توکن ربات |
| `TELEGRAM_ADMIN_ID` | ✅ | ادمین (مجاز خودکار) و تنها کاربر `/usage`. اگر خالی باشد `/usage` برای همه بسته است |
| `SPORTS_API_KEY` | ✅ | کلید SportsAPI Pro |
| `ALLOWED_USERS` | توصیه می‌شود | آیدی‌های مجاز با کاما؛ **همه‌ی این‌ها پیام‌های خودکار می‌گیرند** |
| `TEAM_ID` | ❌ | پیش‌فرض `2817`. ⚠️ با پاسخ واقعی API تأیید کن |
| `LOCAL_TZ` | ❌ | پیش‌فرض `Asia/Tehran` |
| `REMINDER_MINUTES` | ❌ | پیش‌فرض `5,10,15,30,60` |
| `BOT_API_BASE_URL` | ❌ | آدرس پروکسی Bot API |
| `DB_PATH` / `STATE_FILE` / `CACHE_FILE` | ❌ | مسیر نسبی یعنی نسبت به ریشه‌ی پروژه |
| `LOG_RETENTION_DAYS` | ❌ | پیش‌فرض `180`؛ لاگ قدیمی‌تر خودکار پاک می‌شود |

ثابت‌های داخل `settings.py` که ممکن است بخواهی عوض کنی:

| ثابت | پیش‌فرض | معنی |
| :--- | :--- | :--- |
| `AUTO_STATUS_WINDOW_H` | `24` | وضعیت خودکار فقط وقتی بازی کمتر از این ساعت دیگر است |
| `AUTO_STATUS_QUIET_H` | `12` | و از آخرین پیام آن کاربر بیشتر از این ساعت گذشته باشد |
| `REMINDER_GRACE_MIN` | `3` | یادآوری حداکثر این‌قدر دقیقه می‌تواند دیر بیاید |
| `RESULT_CHECK_AFTER_MIN` | `90` | جست‌وجوی نتیجه از این‌قدر دقیقه بعد از شروع بازی |

⚠️ اگر `ALLOWED_USERS` و `TELEGRAM_ADMIN_ID` هر دو خالی باشند، همه می‌توانند دستورها را بزنند ولی هیچ پیام خودکاری فرستاده نمی‌شود.

## 🔔 پیام‌های خودکار (برای همه‌ی کاربران مجاز)

```
هر ۱ دقیقه   → یادآوری ۶۰/۳۰/۱۵/۱۰/۵ دقیقه‌ای   (فقط از کش، بدون مصرف سهمیه)
هر ۱۰ دقیقه  → نتیجه‌ی بازی‌های تمام‌شده + وضعیت خودکار
روزی ۰۸:۰۰   → تازه‌سازی لیست بازی‌ها
```

- ⏰ **یادآوری:** هر یادآوری برای هر بازی و **هر کاربر** فقط یک‌بار می‌رود. اگر ساعت بازی عوض شود، یادآوری‌های جدید برای زمان جدید می‌رود.
- 📊 **نتیجه:** ۹۰ دقیقه بعد از شروع بازی، هر ۱۰ دقیقه چک می‌شود و فقط وقتی API بگوید بازی `finished` است، نتیجه برای همه می‌رود. بعد از ۶ ساعت بی‌نتیجه، بازی رها می‌شود.
- 📡 **وضعیت خودکار:** برای هر کاربر جداگانه چک می‌شود: اگر کمتر از ۲۴ ساعت به بازی بعدی مانده **و** بیشتر از ۱۲ ساعت از آخرین پیامی که به **همان کاربر** رفته گذشته باشد (یا تا حالا پیامی نرفته باشد)، وضعیت بازی بعدی برایش می‌رود.
- 🕒 **«آخرین پیام» از کجا می‌آید؟** از جدول `usage_log` در دیتابیس. هر پیامی که ربات به کاربر بفرستد (یادآوری، نتیجه، جواب دستور، وضعیت خودکار) ثبت می‌شود، پس این زمان همیشه دقیق است و با ری‌استارت از بین نمی‌رود.

### ➕ اضافه کردن یک دستور

۱. در `commands.py` یک تابع `async def cmd_x(update, context)` بنویس.
۲. یک خط به `COMMANDS` اضافه کن. منو، کنترل دسترسی و لاگ خودکار به‌روز می‌شوند.

### 🇮🇷 اضافه کردن نام فارسی تیم یا رقابت

در `formatting/names.py` به `TEAMS_FA` یا `_COMPETITIONS` یک خط اضافه کن. اگر نامی نباشد، همان نام انگلیسی نشان داده می‌شود و چیزی خراب نمی‌شود.

## 🔄 مهاجرت از نسخه‌ی قبلی

- `usage.db` همان‌جا که هست می‌ماند و خودکار به اسکیمای ۴ مهاجرت می‌شود. جدول `match_alerts` دوباره ساخته می‌شود (بدترین حالت: یک یادآوری تکراری برای هر کاربر).
- کلید قدیمی `last_bot_message_time` در `bot_state.json` دیگر استفاده نمی‌شود؛ زمان آخرین پیام هر کاربر از دیتابیس خوانده می‌شود.
- `ICS` و `MATCH_SOURCE` حذف شده‌اند. اگر در `.env` داری، بی‌اثرند.

## 🩺 عیب‌یابی

| مشکل | علت / راه‌حل |
| :--- | :--- |
| `توکن تنظیم نشده است` | `TELEGRAM_BOT_TOKEN` را در `.env` (ریشه) بگذار |
| `JobQueue غیرفعال است` | `pip install "python-telegram-bot[job-queue]"` |
| `SPORTS_API_KEY تنظیم نشده است` | کلید را در `.env` بگذار |
| `TEAM_ID ... در هیچ‌کدام از دو تیم بازی نیست` | `TEAM_ID` اشتباه است؛ پاسخ API را چک کن |
| هیچ هشداری نمی‌رود | `TELEGRAM_ADMIN_ID` و `ALLOWED_USERS` هر دو خالی‌اند، یا زمانش نرسیده |
| یک کاربر هشدار نمی‌گیرد | آیدی‌اش در `ALLOWED_USERS` نیست یا `/start` نزده؛ در `python report.py --user <id>` دنبال `delivery=failed` بگرد |
| `/status` اطلاعاتی نشان نمی‌دهد | `/sync` بزن و لاگ خطای API را ببین |
| `429 Too Many Requests` در لاگ | سهمیه‌ی API تمام شده؛ ربات خودش چند دقیقه صبر می‌کند و تا آن موقع از داده‌ی ذخیره‌شده (`api_cache.json`) استفاده می‌کند |
| `NetworkError / ReadError` در لاگ | قطعی گذرای شبکه یا پروکسی تلگرام؛ کتابخانه خودکار دوباره وصل می‌شود |
| `database is locked` | دو نمونه‌ی ربات هم‌زمان اجرا شده‌اند |
| می‌خواهی یادآوری دوباره برود | `sqlite3 usage.db "DELETE FROM match_alerts WHERE match_uid='...';"` |

چک سریع پاسخ API (برای تأیید `TEAM_ID`، رقابت و ورزشگاه):

```bash
curl -H "x-api-key: $SPORTS_API_KEY" https://api.sportsapipro.com/v2/football/teams/2817/events/next/0
```

## 🛡️ امنیت و حریم خصوصی

- `.env`، `usage.db*`، `bot_state.json` و `api_cache.json` در `.gitignore` هستند. کلید API و توکن را هرگز در Git نگذار.
- `usage.db` متن پیام‌ها و نام و آیدی کاربران را دارد؛ مثل داده‌ی شخصی با آن رفتار کن. لاگ‌های قدیمی‌تر از `LOG_RETENTION_DAYS` خودکار پاک می‌شوند.
- لاگ‌های `httpx` خاموش شده‌اند، چون آدرس درخواست‌های تلگرام شامل توکن ربات است.
